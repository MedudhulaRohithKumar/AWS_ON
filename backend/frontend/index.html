Why CSR?

Everything you need to manage UAT uptime

Designed for the CSR project's infrastructure team — stop emailing each other and use a secure, auditable portal instead.

🎯
Per-Instance Precision

Extend only the exact instance you need. Other UAT servers shut down as normal at 6 PM — CSR uses EC2/RDS tags, not EventBridge rule changes.

🔐
Secure JWT Auth

Role-based access with admin and user logins. Passwords hashed with bcrypt. Every action — login, extend, stop — is logged with IP and timestamp.

⏰
Auto-Expiry

Set a date and time. When the deadline hits, CSR automatically stops the instance and removes the protection tag — no manual cleanup needed.

📊
Admin Insights

Full audit trail, extra-hours cost reports, and a leaderboard showing which teams extend UAT resources most — visible only to admins.

☁️
AWS-Native

Runs as a Lambda function with an IAM role — no credentials in code. Data stored in S3. Works with your existing EventBridge + Lambda setup.

🚀
One-Click Extend

Log in, pick your server, choose a deadline — done in under 30 seconds. No AWS console access required for your team members.

How It Works

Simple. Safe. Surgical.

1
Log in to CSR

Use your username and password. Admins see everything; users see only their team's servers.

2
Pick a Server & Set a Deadline

Select the EC2 instance or RDS database from the dashboard and choose when it should turn off — any date and time.

3
CSR Starts It & Tags It

The instance starts immediately. A EXTEND_UNTIL tag is added. Your existing shutdown Lambda sees this tag and skips the instance.

4
Auto-Stop at Deadline

At the chosen time, CSR stops the instance and removes the tag. Other UAT servers were never affected.
