CSR — Cloud Server Resurrector

The complete guide to using the UAT Instance Control Portal.

Overview

CSR (Cloud Server Resurrector) is a secure web portal that lets your team temporarily keep UAT EC2 instances and RDS databases running beyond the normal 6 PM shutdown — without disabling any infrastructure rules or affecting other environments.

Your existing EventBridge rules continue to fire every hour from 6 PM to 2 AM. The shutdown Lambda now checks each instance for a EXTEND_UNTIL tag before stopping it. Only the specific instances you extend via CSR are skipped.

Project: CSR · Region: ap-south-1 · Shutdown: 6 PM IST · Work Hours: 9 AM – 6 PM IST

Getting Started

Step 1 — Get Your Login

Ask your CSR administrator for a username and password. Accounts are managed directly in the Admin Panel.

Step 2 — Sign In

Navigate to the CSR portal URL and click Sign In. Enter your credentials and you'll be redirected to your dashboard.

Your session lasts 8 hours. After that, you'll be prompted to log in again.

Step 3 — View Available Servers

The dashboard shows all UAT servers registered by your admin, along with their current live status (Running / Stopped).

How to Extend a Server

  1. Find the server card on the dashboard and click "Extend / Start".
  2. In the modal, select the date and time (IST) until which the server should remain running.
  3. Review the preview and click "⚡ Extend Now".
  4. CSR will:
    • Start the instance immediately (if stopped)
    • Apply a EXTEND_UNTIL tag to the instance
    • Schedule an auto-stop at your chosen deadline
  5. The server card will show a green "Extended until…" banner with a countdown.
Multi-day extensions work. If you extend until June 23rd at 11 PM, the instance will be protected through all nightly shutdown events (6 PM, 7 PM… 2 AM) until that deadline.

Updating an Extension

Click "Extend / Start" again on an already-extended server and pick a new time. CSR will update the deadline and reschedule the auto-stop.

Stopping Early

Click "Stop Now" on any running server to stop it immediately, remove the protection tag, and cancel the scheduled auto-stop.

Auto-Stop Explained

When you extend a server, CSR creates a one-time EventBridge Scheduler that fires at exactly your chosen deadline and invokes the CSR Lambda to stop the instance.

Example timeline for "Extended until June 23, 11:00 PM IST": June 23, 6:00 PM → EventBridge fires → Shutdown Lambda runs → Sees EXTEND_UNTIL = 2026-06-23T17:30:00Z (> now UTC) → SKIPS June 23, 7:00 PM → Same → SKIPS ... June 23, 11:00 PM → CSR Scheduler fires → Stops instance → Removes tag → Done ✅ June 24, 6:00 PM → EventBridge fires → No tag found → Instance stops normally
Important: Only the instances you select are protected. All other UAT instances shut down at 6 PM as normal.

Admin Guide

Managing Users

Go to Admin Panel → Users to:

  • Add new users with username, email, password, and role (user/admin)
  • Change roles or reset passwords
  • Deactivate accounts (they cannot log in but data is preserved)

Managing Servers

Go to Admin Panel → Servers to:

  • Add Manually: Enter the EC2 Instance ID or RDS DB Identifier, display name, and type
  • Discover from AWS: Auto-scan for EC2 instances tagged TURN_UP = UAT_EXTEND
  • Remove servers from the portal (they are not deleted from AWS)

Activity Log

Every action — login, logout, extend, stop, add user — is recorded with username, timestamp (IST), IP address, and details. Use the search bar to filter.

Extra Hours Report

Shows how many hours each instance ran outside normal working hours (after 6 PM). Useful for understanding cloud cost impact of UAT extensions.

Leaderboard

Ranks users by total extra hours of UAT uptime they've requested. Top 3 shown on a visual podium.

AWS Architecture

Components

  • CSR Lambda (Python 3.13, FastAPI + Mangum) — the backend API
  • API Gateway (HTTP API) — routes HTTP requests to the Lambda
  • S3 Bucket instance-rds-extend — stores JSON data files
  • EventBridge Scheduler — one-time schedules per extension for auto-stop
  • S3 Static Website — serves the frontend HTML/CSS/JS

Data Files in S3

  • users.json — user accounts
  • activity.json — full audit log
  • servers.json — registered servers
  • extensions.json — extension records

Lambda Environment Variables

S3_BUCKET_NAME=instance-rds-extend AWS_REGION=ap-south-1 JWT_SECRET=your-secret-here CSR_LAMBDA_ARN=arn:aws:lambda:ap-south-1:ACCOUNT:function:csr-backend SCHEDULER_ROLE_ARN=arn:aws:iam::ACCOUNT:role/csr-scheduler-invoke-role ALLOWED_ORIGINS=https://your-s3-static-site.s3-website.ap-south-1.amazonaws.com

Security

  • Passwords hashed with bcrypt (12 rounds) — never stored in plaintext
  • Authentication via JWT tokens (8-hour expiry)
  • All AWS operations via IAM Role on the Lambda — no credentials in code
  • Admin routes protected by role check — users receive 403 if they try to access admin APIs
  • All actions logged with IP address and timestamp for audit
  • S3 bucket is private — frontend is served from a separate static site
Change JWT_SECRET immediately after first deployment. Use a random 64-character string. Store it in AWS Secrets Manager or as a Lambda env var.

Frequently Asked Questions

What if I extend past 2 AM?

Works perfectly. The EventBridge rules fire until 2 AM. After 2 AM, no more shutdown attempts are made by EventBridge. Your instance stays running until CSR's scheduled stop fires at your chosen deadline.

Can I extend an instance that's already running?

Yes. If it's already running (from before 6 PM), CSR just applies the protection tag so the 6 PM shutdown skips it. The instance isn't restarted.

What if two people extend the same instance?

The second extension overwrites the first. The deadline is updated to whichever was set last. Both actions are logged in the activity trail.

Does CSR affect production instances?

No. CSR only operates on instances explicitly registered by an admin in the Server Registry. The shutdown Lambda patch also only checks for the EXTEND_UNTIL tag — production instances will never have this tag.

Where do I find the portal URL?

Ask your CSR administrator. The URL is your S3 static website URL or a custom domain if one was configured.
